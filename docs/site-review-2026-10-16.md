## 一、總結

產品概念清楚：「拍照 → AI 辨識 → 自動定價 → 分享連結接單」，價值主張也講得很直接（60 秒上架、0% 抽成）。對 AI 搜尋與 SEO 的基礎做得比一般新創好，有 llms.txt、FAQ／Organization／Product schema、canonical，robots 也有寫。

**最大的問題是：網站本身是一個「台灣本地、日本代購」產品，和「國際華語市場」這個定位差很遠。** 語言、幣別、金流、物流、案例都只服務台灣賣家。要往國際華語市場走，問題不在 SEO 細節，而是產品和網站都得在地化。

| 面向 | 評估 |

## 二、國際華語市場適配（核心問題）

| 項目 | 現況 | 對國際華語市場的影響 |
|---|---|---|
| 語言 | 只有 `zh-Hant`，沒有 `hreflang`；送 `Accept-Language: zh-CN` 也不會分流 | 中國大陸、新馬、北美簡體用戶讀起來不順，Google／百度也不會把網站當成簡中結果 |
| 用語 | 台灣用語（上架、方案、賣貨便、好賣家） | 港澳、新馬的慣用語不同 |
| 幣別 | 只有 NT$；schema 寫 `priceCurrency: TWD` | 海外賣家看不出自己要付多少 |
| 匯率定價 | 後台原價可用 7 種幣別輸入（日圓、韓元、泰銖、美元、越南盾、歐元、澳幣），但售價固定換算成新台幣顯示；首頁文案只寫「日幣自動換台幣」 | 適合人在海外、賣給台灣客人的賣家；要賣給馬來西亞、香港、美國等當地客人，需要以當地幣別（MYR、HKD、USD 等）顯示售價與結帳，目前不支援 |
| 金流 | FAQ 說「平台不代收款項，可用轉帳、LINE Pay」，Pro 方案寫「統一金流後台串接」 | 兩者互相矛盾；而且統一金流和 LINE Pay 都是台灣的服務，海外沒有可用的收款方式（Stripe、PayPal、FPX、PayNow、Alipay HK 等） |
| 物流 | 推薦賣貨便、好賣家（7-11 台灣） | 只限台灣 |
| 社群分享 | 以 LINE 為主 | 港澳、新馬主要用 WhatsApp，中國用微信，北美華人用微信或 WhatsApp |
| 情境 | 首頁的「回國了不想用怎麼辦？」、「下一趟出國」、櫻花圖都是台灣人去日本代購的情境 | 海外華人的情境（例如在美國代購回亞洲、在日本賣給華人）沒有被涵蓋 |
| 法規頁 | 公司是台灣的卉田國際（統編 91093506） | 海外用戶需要知道資料跨境處理的方式（GDPR、PDPA 等）；隱私權政策要另外確認 |

**建議分階段做：**

1. **第一階段（低成本）**：網站加入簡中版（`/zh-hans/`），首頁與 about 加 `hreflang`（zh-Hant-TW、zh-Hant-HK、zh-Hans、x-default）。定價頁顯示 USD 參考價，或依 IP 顯示當地幣別。
2. **第二階段**：產品端支援任意幣別組合定價，WhatsApp 和微信分享，以及一個國際金流（Stripe 最快）。
3. **第三階段**：針對各市場寫情境內容，例如「馬來西亞華人日本代購」、「在美國做韓貨團購」。

另外注意：網站本身在定位上也自相矛盾。about 頁寫「代購只是其中一種使用情境，**不是主要市場**」，但首頁 FAQ 和部落格幾乎全是日本代購內容。建議先決定主打哪一群人，再讓全站一致。

## 三、內容與可信度

1. **部落格有計算錯誤（建議立刻修）**
   `/blog/japan-cosmetics-daigou-guide` 寫「日幣 1,280 × 當天匯率 4.62 = 台幣 5,914」。4.62 是「台幣換日幣」的匯率，正確算法是 1,280 ÷ 4.62 ≈ NT$277。賣「匯率自動定價」的產品在定價教學裡算錯匯率，傷害可信度很大，AI 引用時也可能把錯誤散播出去。
2. **品牌名稱不一致**：首頁用「我拍 VOVOSnap」，部落格 title 用「｜vovosnap」（小寫），llms.txt 用「我拍｜開店平台」。建議統一，對 AI 實體辨識比較好。
3. **「1000+ 位賣家」的社會證明**：sitemap 裡公開的店舖只有 37 間（未公開的店舖無法從外部驗證）。如果這個數字包含沒有上架的註冊帳號，建議改成能查證的說法，以免被質疑。
4. **範例店舖 `/s/default/` 品質不佳**：首頁「查看範例店舖」連過去的店有日文原文商品名（例如「★SALE★グラフィックバリエーショントレーナー」）、「價格未提供」，還有醫藥品。這是潛在客戶第一個看到的實際成果，建議換成精心整理過的示範店。
5. 部落格有一篇淘寶相關文章，但網站沒有簡中版，讀者對不上。

## 四、SEO／GEO（AI 搜尋）

**做得好的地方**

- 有 llms.txt，內容是結構化的核心事實和方案表，這點很少見，值得保留
- 首頁和 about 有 FAQPage、Organization、SoftwareApplication schema，部落格文章有 BlogPosting 和日期
- canonical、OG 和 Twitter card 都齊全，圖片都有 alt
- 部落格標題用問句寫成（「拍照上架軟體通常怎麼收費？」），很適合被 AI 引用

**問題**

| 問題 | 說明 |
|---|---|
| sitemap 被商品頁稀釋 | 1,677 個 URL 中有 1,617 個是 `product?code=manual-…` 這類用戶商品頁，內容大多很薄（約 200 字）。搜尋引擎會把大量低品質頁面算在 vovosnap.com 頭上 |
| sitemap 跨網域 | 有 22 個 `sanyang.vovosnap.com` 的 URL 放在主網域 sitemap 裡，沒有做跨網域驗證的話 Google 會忽略 |
| 商品頁 title | 一律是「店名 — 商品詳情」，沒有商品名稱，對搜尋幾乎沒有價值 |
| 店舖 og:image | 都用平台的 logo-3.png，在社群分享時看不出是哪一家店 |
| 商品頁顯示空值 | 出現「顏色數：0」、「色數：0」，品牌欄位填的是分類 |
| 用戶店舖預設 `index, follow` | 敏感類別的店舖會直接被索引在主網域下（見第五節） |

**建議**：主 sitemap 只放官網頁和部落格；用戶店舖改用獨立 sitemap，並設品質門檻（例如商品有描述、有價格才收錄）。商品頁 title 改成「商品名｜店名」。

## 五、店舖內容合規風險

公開店舖裡看到：

- **醫藥品代購**：範例店有「大正口內炎軟膏」，分類標的就是「醫藥品」。依台灣《藥事法》，未經許可販售藥品違法，賣到其他國家也有各自的藥品法規。範例店是平台自己的門面，風險更直接。
- **宗教法事服務**：例如「龍鳳桃花姻緣燈 NT$6,000」，這類內容容易出現消費糾紛和療效、功效宣稱的問題。
- **保健食品**：有功效宣稱的風險。

about 頁已經寫了「不適合販售違法商品」，但從公開店舖看，**沒有上架前的類別審核**。走國際市場後，各地法規不同，建議：

- 建立禁售／限售類別清單，AI 辨識到藥品、菸酒、保健食品時提醒或阻擋
- 範例店立刻移除醫藥品
- 敏感類別的店舖預設 `noindex`

## 六、技術與安全

| 項目 | 結果 | 建議 |
|---|---|---|
| HTTP → HTTPS | `http://vovosnap.com/` 直接回 200，**沒有轉址** | 在 Cloudflare 開啟「Always Use HTTPS」 |
| www → 根網域 | 302 | 改成 301 |
| 安全標頭 | 沒有 HSTS、CSP、X-Frame-Options、X-Content-Type-Options | 店舖有收單和後台，至少要加 HSTS 和 X-Frame-Options |
| 首頁速度 | 有 CDN 快取，TTFB 約 0.6 秒 | 良好 |
| **店舖與商品頁速度** | TTFB 約 **2.2–2.7 秒**（沒有快取） | 海外用戶連過來會更慢，建議用 edge cache 或 stale-while-revalidate |
| 字型 | 載入 Noto Sans TC 和 Noto Serif TC 共 6 個字重 | 繁中字型檔很大；加簡中版時要再載 SC 字型，建議減少字重或做子集化 |
| 分析工具 | 有 GA4 和 web-vitals | 良好 |
